## 公開時の説明案

CompEditor 0.4.0 では、Next Edit Suggestions（NES）の差分表示を再利用するよう改善し、Java／Python の単一ファイル実行と、期待出力との比較を追加しました。

### 変更点

- **NES の差分表示を再利用**：同じ候補をスクロールやウインドウのサイズ変更で表示し直すとき、変更前後の本文と差分範囲を再利用します。候補の入れ替え、編集に伴う再調整、別文書への移動では必要な表示データを更新します。文書間でキャッシュを共有せず、既存のプレビュー、採用、Undo／Redo の操作を維持します。速度向上率や Copilot の応答時間の改善を保証する変更ではありません。
- **Java／Python の実行と停止**：保存済みの単一ファイルを、ツールバー／メニューと既定の Command-R から実行できます。停止は停止ボタンまたは Command-. です。標準の保存・実行環境選択を経て、作業フォルダ、使用した実行環境、終了状態、標準出力と標準エラーを文書の実行パネルに表示します。Python は選択した Python 3、Java は同梱または選択した JDK を使用し、Java のコンパイルに失敗した場合は実行しません。外部依存物を含むプロジェクトのビルドや一般的なテストランナーは対象外です。
- **標準入力と結果の確認**：実行開始時の入力に加え、対話入力の送信と EOF に対応します。標準出力と標準エラーは混ぜず、各10 MiBまで保持し、以降の省略を示します。実行後にソースを編集した場合は、以前の実行結果であることを示し、古い位置への移動を防ぎます。文書を閉じる場合やアプリ終了時には、所有している実行プロセスの停止と後片付けを行います。
- **期待出力ファイルの読み込み・比較**：`.out`、`.txt`、任意の拡張子、拡張子なしの通常ファイルを同じように選択できます。内容は strict UTF-8、上限10 MiBで検査し、先頭の UTF-8 BOM だけを除きます。空ファイルも有効です。文字コードの自動推測、同名ファイルの自動探索、複数ケースの永続管理は行いません。
- **比較方法と不一致の表示**：既定では CRLF／CR を LF にそろえ、厳密モードでは改行も区別します。どちらも末尾改行、空白、タブ、空行、大文字小文字、Unicode 正規化の差を勝手に無視しません。比較対象は標準出力だけです。終了 code 0・省略なし・デコードエラーなしの場合だけ一致とし、停止や実行失敗を一致扱いしません。最初の相違の行・列（列はUTF-8バイト単位）、実際のバイト値、EOF、行数、末尾改行と空白の可視化を確認できます。大きい出力では一致判定に全体を使い、詳細表示の範囲を制限します。
- **読み込んだ時点の内容を保持**：期待出力は読み込み時のスナップショットです。外部変更は「再読込」で明示的に反映し、「解除」で比較対象を外せます。読み込み・実行・比較モードの切り替えで古い非同期結果が新しい選択を上書きしないようにしています。

実行・比較機能は、標準入力、期待出力、実出力を外部へ送信しません。実行するプログラム自体を隔離する sandbox ではなく、プログラムのファイル操作や通信を制限する機能ではありません。既存の Copilot のコード送信同意、実験的な自動 NES の初期オフ、[利用統計の説明](USAGE_STATISTICS.md)は継続します。

### 対応環境・配布方針

**macOS 26以降、Apple Silicon（arm64）向け**です。Intel／Universal 版としては配布しません。今回のネイティブ確認は macOS 27 / Xcode 27 環境で行われ、macOS 26 上の実行確認を意味しません。

従来と同じ匿名の ad-hoc 署名を使用し、新しい Developer ID 署名や Apple 公証は行いません。更新は既存の Sparkle 2.10.0、承認済み公開鍵、HTTPS フィード、必須のフィード／アーカイブ署名検証を維持します。起動時の更新通知はメタデータの確認であり、署名検証なしにアプリをインストールするものではありません。配布 ZIP と appcast の署名・検証結果は、完成した v0.4.0 アセットについて公開前に記録します。

### 確認できた範囲と残る制限

機能統合版では、独立レビューと main の CI が通っています。親担当者の macOS 確認では、Debug ビルド、通常 hosted テスト194件、排他的 NES テスト5件、ツールバー、実行パネルと NES の併用、パネルの表示／非表示・ウインドウのサイズ変更・メニューからの NES 採用、実行の所有関係、古い結果からの移動防止、文書終了・アプリ終了時の後片付けが通りました。期待出力の改行統一／厳密比較、BOM、読み込みエラー、再読込／解除、狭幅 Dark 表示も確認されています。統合 main の CI はパッケージ、hosted、排他的 NES、オフライン検査、Release ビルドの起動 smoke を含め成功しています。

**手動の Tab による NES 採用、仕切りの直接ドラッグ、VoiceOver の読み上げは未確認**です。これらを確認済みとして案内しないでください。0.4.0 / build 862 の配布用ビルド、実際の ZIP／appcast の監査と署名検証、ダウンロードした正式配布物での動作や更新インストールは、上記の機能テストとは別の公開前作業です。

CompEditor は非公式の CotEditor 派生版です。Apache-2.0、同梱依存物の各ライセンス、変更していない元のアートワークの帰属・非商用配布・改変不可などの条件を保持します。問い合わせ先は [GitHub Issues](https://github.com/KDU-i/CompEditor/issues) です。

## 親担当者向け：レビュー後のネイティブ配布手順

1. この準備 PR の独立レビューを反映し、マージ後の正確な commit と tree を記録します。v0.3.1 のタグ／配布物は変更しません。既存の QA アプリや build 861 の配布物を build 862 として流用しないでください。
2. レビュー済み commit を checkout した Mac で、承認済みのキャッシュ・固定依存物を使い、新しいソース／ビルドパスで既存のスクリプトを実行します。下記の変数は親担当者が既存の承認済み入力に設定します。ユーザーのアプリや設定を上書きしません。

   **ソース出力の前提確認**：既存の `prepare-release-source.py` は改変一覧の基点として `efd522f9fc9362a5211aef528b96a87dcad11335` を参照します。Mac 側で `git cat-file -e efd522f9fc9362a5211aef528b96a87dcad11335^{commit}` が成功することを先に確認してください。今回の Cloud checkout にはこの object がなく、公開 origin への exact-SHA fetch も `not our ref` でした。そのため Cloud での clean export の追加検査は未完了です。Mac 側にも object がなければ包装を止め、元の承認済み履歴の入手か、改変一覧の基点の扱いについて独立レビューを受けてください。基点を便宜的に置き換えたり、改変一覧・帰属処理を省略したりしません。

   ```sh
   RELEASE_SOURCE_TREE="$release_commit" zsh Scripts/build-release-candidate.sh \
     "$new_source" "$new_build" "$cached_packages" "$approved_servers" \
     "$node_executable" "$jdk_home" "$official_copilot_server"
   ```

   同梱の JDK／Node／言語サーバー／Copilot サーバーと Swift 依存物は既存の固定版・ハッシュ・対応ソースに合わせます。新たな実行環境のダウンロードや全体インストールは行いません。ビルドは原来の配布 identity `dev.local.SemanticEditor`、arm64、Release で行い、QA 用 bundle ID／設定を配布しません。既存スクリプトの coverage 無効化、匿名パスマップ、strip、ライセンス追加、ad-hoc seal、監査を維持します。
3. `Candidate.xcarchive/Products/Applications/CompEditor.app` の `CFBundleShortVersionString=0.4.0`、`CFBundleVersion=862`、最低 macOS 26、arm64、署名、同梱実行環境を検査します。全ネストの署名と audit を確認し、coverage、個人パス、ログ、認証キャッシュ、資格情報、秘密鍵、QA 専用データを梱包しません。公開鍵／フィードと updater の安全設定は既存値から変えません。
4. 完成したアプリと同じソースを監査して梱包します。既存スクリプトは、梱包前と完成 ZIP の両方を監査します。

   ```sh
   python3 Scripts/package-release-archive.py \
     --input "$new_build/Candidate.xcarchive/Products/Applications/CompEditor.app" \
     --output "$release_assets/CompEditor-v0.4.0-macos-arm64.zip"
   python3 Scripts/package-release-archive.py --input "$new_source" \
     --output "$release_assets/CompEditor-v0.4.0-source.zip"
   ```

   第三者ランタイム等の対応ソースは実際の同梱版・変更内容と照合し、`CompEditor-v0.4.0-corresponding-sources.zip` として同じアクセス条件で用意します。以前の対応ソースを使う場合も、入力と内容・ハッシュの一致を検証してから採用します。監査結果は秘密情報不在の完全な保証ではありません。
5. 既存の公式 Sparkle ツールと承認済みの専用 Mac Keychain アカウントで、完成 ZIP とフィードを署名します。**資格情報・秘密鍵の抽出、表示、ファイル保存、鍵の再生成、Keychain 権限の変更は行いません。Developer ID／公証は追加しません。** 同じ公開鍵によるアーカイブ検証と公式ツールによるフィード検証を行い、署名後に配布物を再監査します。feed は `sparkle:version=862`、`sparkle:shortVersionString=0.4.0`、最低 macOS 26、実際の ZIP サイズ・署名と、固定 URL `https://github.com/KDU-i/CompEditor/releases/download/v0.4.0/CompEditor-v0.4.0-macos-arm64.zip` を参照させます。既存の HTTPS／署名／未保存文書保護を弱めません。
6. 同じ一組のアセットを用意します：アプリ ZIP、ホストソース ZIP、対応ソース ZIP、`appcast.xml`、`SHA256SUMS`、`provenance.json`、`NOTICE.md`、`THIRD_PARTY.md`、`ARTWORK_ATTRIBUTION.md`、`USAGE_STATISTICS.md`。来歴には正確な commit／tree、ツールチェーン、入力・アセットのハッシュを記録し、ローカルパスや秘密を含めません。公開時の説明にはアプリ、ホストソース、対応ソースの固定ダウンロードリンクを入れます。リンク先は v0.4.0 の公開前には存在しません。
7. 正確な release commit で必要なネイティブ検査と配布監査を完了し、親担当者の最終判断後に初めてタグ／GitHub Release／latest フィードを公開します。実ダウンロードの ZIP と公開 appcast を再取得し、バージョン、サイズ、ハッシュ、署名、対応ソースとリンクの一致を確認します。更新インストールの確認を行う場合も、親担当者が承認した分離環境を使い、ユーザーの利用中アプリを置き換えません。

この Cloud 準備では、バージョン設定と本書以外のコード、更新ポリシー、配布スクリプト、ライセンス、実行環境を変更しません。ネイティブ包装・署名・公開の成功は主張しません。
