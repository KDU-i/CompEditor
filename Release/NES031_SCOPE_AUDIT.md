## Corrections to earlier residual descriptions

- **NES word/line partial adoption:** not missing at the pinned VS Code commit. Those commands operate on ghost text, not inline edits.
- **Multi-file batch acceptance:** not the referenced upstream behavior. The actual difference was navigation/transplant, now implemented for synchronized known targets.
- **Multiple hunks:** the public API already permits a wide single range containing several changes. The missing pieces were derived hunk boundaries, preserving edits in unchanged islands, precise coloring, and last-change caret; these are now addressed with bounded independent host logic.
- **Inline-first:** source-compatible default priority. Sequential provider startup was the difference and is replaced by parallel work.
- **Fixed 50 ms:** removed for joint and NES. Ordinary inline-only debounce is outside the fixed NES-delay claim.
- **Current-document-only history:** no longer a blanket host restriction; all already-requested documents are retained for their open lifetime and closed when the owned model and its live views close, or language permission narrows. This does not grant general workspace context.
- **Focusable hover:** general editor UI capability, not evidence that NES can steal keys from a focused control. The relevant eligibility/ownership guard is tested with a real focused native input control.

## Provider/API feasibility and remaining boundaries

S1:173–178 documents incremental synchronization and didFocus. S1:325–387 exposes NES requests, alternatives, per-item URI/version/range/text, show and accept feedback. These support parallel requests, real edit history, known cross-file transfer and host-derived hunks; none is classified as an unavoidable API limitation.

S1:392–422 additionally exposes `cacheTelemetryContext` and `textDocument/reportCachedInlineEdit`. The earlier broad assertion that cache support is absent was incorrect. This API reports a **client cache serve** and its lifecycle; it does not supply a model/prefetch operation or the original source snapshot of an unknown target. This implementation retains/rebases the currently displayed opportunity and requests fresh provider results; it does not create new cache opportunity IDs or replay a disposed cached result as a new display. Thus ordinary provider feedback remains appropriate. If a new independent client cache is added later, this reporting protocol is available and must be used with unchanged opaque context and unique occurrence IDs.

Private prediction/model selection, experiment assignments, provider-internal cache/prefetch behavior and exclusion/context policies cannot be established from the public host plus the packaged LSP contract. We do not assert that they are impossible to implement, or that an empty response proves provider parity. No undocumented request, fabricated future edit, credential extraction, or alternate unofficial model is used to claim equivalence.

An unknown foreign edit still lacks a locally owned matching original snapshot/version. The new host path separates navigation from adoption: only an explicitly opened DirectoryDocument provides authority to its project root. Exact ordinary-source targets are checked against local exclusions, hidden/dependency/secret-name and content guards, symlink containment and descriptor-relative regular-file reads. First Tab opens the normal document model without changing its text, preserving any existing unsaved buffer; a fresh foreground NES request establishes actual ownership. Only its validated response can later adopt. No unknown server version is assigned to local contents, and the unowned edit itself is never transplanted.

This adds a bounded project capability, not background workspace indexing. It neither enumerates directories nor uploads other project files or announces a broader workspace to the provider. It reads only the exact target plus checked exclusion/configuration/registration metadata; other-language opt-in still applies. Existing source permissions/consent remain required. Metadata reads have 64 KiB limits and source reads 4 MB; invalid/binary/changed inputs fail closed. Registered Git worktrees and separate Git directories now resolve their own/common administration, with linked-worktree reciprocal gitdir/commondir checks. Related include/excludesFile declarations are interpreted inside checked project/repository/admin and standard Git-configuration locations. Unrelated external pointers, source/object/credential files, unreadable or unsupported metadata fail closed before a target is synchronized. Background indexing is not independently required by the original twenty-item evidence. Secret detection is conservative name/literal screening, not proof that arbitrary source text contains no secret.

The old2048-grapheme/two-million-product cutoff was a correctable host difference, not an API limitation. It is removed. An independent sparse-edit shortest-path search decomposes large single-line and multiline candidates, with exact UTF-16 tokens and no quadratic matrix. It preserves edited islands and final-hunk caret above the old limits. Like V7:600–618, actual exploration has a50ms budget; if exploration expires, the validated outer edit remains available. This is a shared resource-bounding policy, not a promise of identical timeout thresholds/results on different hardware or identical VS Code line/subword heuristics. Tokenization/minimization are preprocessing, not a total UI latency guarantee. Tests explicitly cover an exhausted budget and exact safe reconstruction; no candidate is called unsupported merely for crossing the old size threshold.

No upstream implementation was copied; referenced MIT licenses were inspected. Existing Apache-2.0 project attribution remains unchanged.

General background workspace indexing/model context is not advertised or classified as backend-impossible.
-8documents/32histories: actual correctable host differences, now removed; not API limitations or common safety counts. Lifecycle close and ten-second expiry remain.
- Large diff: fixed size/product cutoff was a correctable host difference, now removed. The remaining actual computation-time budget is also explicit in the pinned VS Code source. Exact heuristic/pixel/model identity remains unclaimed.

Actual NSTextInputClient kana/kanji composition, Tab/Esc ownership, delayed reply refusal and post-commit candidates are tested. ## Exclusion and worktree correction after 0b1e review

The0b1e P1 was valid: trimming leading whitespace and ignoring core.ignoreCase could allow files that Git excluded. The independent three fixtures (Sensitive.py, private/normal.py, and a leading-space filename) are now rejected. The old custom glob parser is removed. Native Git check-ignore --no-index evaluates unchanged rule bytes and case/Unicode settings in a private metadata-only shadow repository. It never opens the original working tree, index, object database, hooks or remote configuration paths. Git exclusions cannot be negated by a separate .ignore or .copilotignore layer.

The0b1e P2 is addressed for normal linked worktrees and --separate-git-dir repositories, rather than treating the presence of a pointer/include/excludesFile as unsupported. Only fixed administration/registration names are inspected during discovery; linked worktrees require the common objects/HEAD structure and reciprocal gitdir/commondir relation. Configuration values are parsed from bounded in-memory stdin with includes disabled, returning only ignoreCase/precomposeUnicode/excludesFile/worktreeConfig/include control keys. Referenced metadata must stay in the selected project, its discovered enclosing/conventional main repository, validated Git administration, or recognized system/user Git configuration locations. Objects, refs, logs, hooks, indexes, supported code/key/database file types and unrelated outside paths are not read as configuration. Rules and a newly generated minimal configuration live only in a new private0700 temporary directory, which is removed after the check. No existing file/Keychain permission is changed.

Git child processes receive a clean environment and only the shadow working directory. They execute config parsing and check-ignore, with no shell, helpers, hooks, source content or network operations. Original configuration bytes are parsed only in local memory/stdin; no raw config copy is persisted and only the specified control keys are returned. Remote URLs and credential values are not selected, logged or transmitted. Metadata files are regular UTF-8/NUL-free files read with O_NOFOLLOW,64KiB each/1MiB cumulative; include recursion is bounded to Git's ten include levels, command output is capped, each child has a3s kill deadline within a5s resolution budget. Errors, unreadability, cycles, unsupported condition semantics or unapproved environment overrides reject the candidate. This is a resource/safety boundary, not a total latency guarantee. A usable installed /usr/bin/git is required; failure does not send a target.

Root-local and checked administrative includes, common info/exclude, per-worktree config, gitdir/gitdir-i and onbranch conditions are supported. Unknown conditions (including remote-URL predicates) fail closed rather than extracting remote credentials or omitting potential exclusions. Tests compare native Git and policy outcomes for case, leading/escaped spaces, POSIX character classes, negation/parent rules, ordinary allowed files, actual linked worktrees, local/admin includes and conditional matches/nonmatches. Native controller tests verify the three excluded targets never navigate/synchronize, and an allowed real-worktree target still re-requests/adopts while dirty source/target state survives.

Primary pattern/config references: [Git gitignore](https://git-scm.com/docs/gitignore) and [Git config](https://git-scm.com/docs/git-config). Actual differential tests use installed Apple Git2.54.0; rolling documentation is not a claim that every newer condition is implemented. No Git source was copied or redistributed.

Opening a subfolder of a Git worktree also preserves enclosing Git rules. Discovery checks only fixed .git names along its ancestor chain, stops at the filesystem root, and copies only the exact ancestor rule files needed for the target. Rules remain anchored at the repository root in the shadow. Checked enclosing/main-tree configuration references may be read as metadata, but source eligibility stays strictly inside the actually opened DirectoryDocument. Native coverage opens a nested folder of a real linked worktree, rejects ancestor-excluded targets and an otherwise ordinary file outside the opened folder, and still permits the in-scope fresh target. No parent directory contents are enumerated or supplied as background context.

Relative core.excludesFile paths are resolved from the enclosing worktree root, including when only a nested folder is open. The native exclusion case uses that layout so a missing file in the opened subfolder cannot silently erase the enclosing rule. Cancelled response parsing stops before starting further metadata checks.

## Conditional-config correction after 8f57 review

The8f57 P1 was valid: serializing includeIf wildmatch into a Gitignore line changed the meaning of trailing spaces and CR. That adapter is removed. Conditions now use Git's config-condition wildmatch through an isolated generated config and a generated marker file. Only a synthetic candidate string is placed in its remote.url field; no actual remote URL or authentication value is selected from the original configuration. Git reads this generated query with includes enabled, and the only include path is the generated private marker. Original user configuration continues to be parsed in memory/stdin with includes disabled and only the established control-key allowlist returned. Original include/excludes paths still pass the same authority/regular-file/content/resource checks before reading.

The selected Git source confirms that both onbranch and hasconfig condition matching use wildmatch with WM_PATHNAME. This host uses the latter as a native matcher for the former's prepared pattern and checked branch. Gitdir preparation retains home/relative/implicit-prefix/trailing-directory handling, including the literal including-directory prefix for ./ patterns. ASCII case folding is applied only for gitdir/i patterns without bracket syntax; bracket-bearing case-folded conditions fail closed instead of approximating Git's special range/class semantics. This explicit compatibility boundary is not a blanket worktree/include refusal. Native matcher support must pass both a positive and a negative control before any condition can be treated as false. Literal tabs in config subsection names are preserved separately from config-value escaping.

The differential script compares actual conditional config plus native exclusion with the full app target policy, so both missed includes and incorrectly activated includes are visible. It covers trailing space/CR/tab, quoted/backslash patterns, character classes, case, Unicode, directories containing whitespace/CR/quotes/brackets, relative prefixes and positive ordinary targets. Unsupported case-folded bracket cases are separately labeled conservative refusal, not exact-parity successes. Native UI uses a registered worktree with a trailing-space admin directory, false space/CR onbranch conditions and a true gitdir condition; excluded targets must never navigate or ever emit didOpen. An in-process autosavingDelay fixture preserves the intended unsaved-document precondition and is restored on leaving the fixture, without changing persisted settings.

Behavioral references: [Git condition evaluation](https://github.com/git/git/blob/v2.54.0/config.c) and [wildmatch](https://github.com/git/git/blob/v2.54.0/wildmatch.c). No Git source or binary is copied into the app. Broad Linux Cloud results reported by the parent are separate evidence, not claimed as execution of that unavailable private diff on this Mac.
