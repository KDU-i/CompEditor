# CompEditor 0.3.1 (build 861) — unreleased candidate

NES now uses green inline insertions, red removed text, compact replacement previews, and responsive stacked/side-by-side line differences. The target has a blue navigation indicator. Clicking it only navigates; proposal surfaces never apply on click. Tab accepts edits on the current or adjacent target line and can continue through visible edits after acceptance. Indentation and ordinary completion take priority over NES. Compatible input rebases displayed candidates; conflicting input dismisses them. Scrolling and resizing reposition previews instead of canceling them. Undo/Redo suppress automatic regeneration until fresh editing or an explicit request.

The host minimizes common unchanged prefixes/suffixes before presentation and application, leaving the caret at the final actual change. Preview does not change text or Undo history. Current-document, language, epoch, revision and UTF-16 snapshot validation, IME and multi-caret refusal remain mandatory.

This is a host behavior change, not a claim of identical Copilot model output, provider history, prefetch, latency or experiment settings. The existing official pinned server, authentication, update public key/feed, privacy boundary and signing mechanism remain in use. The host still accepts one primary edit, not a cross-file or multi-hunk transaction. No VS Code implementation was copied; public MIT-licensed sources were used as behavioral references. Existing notices are retained.

Release remains gated on native acceptance, independent review and exact-tree distribution verification. Do not merge, tag, publish, change the latest feed, or install over the user's application without the parent review decision.

Expected assets: `CompEditor-v0.3.1-macos-arm64.zip`, matching source and corresponding-source ZIPs, SHA256SUMS and signed appcast.xml. The app and feed must both declare 0.3.1/build 861; fixed download links must use tag v0.3.1.
