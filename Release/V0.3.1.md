# CompEditor 0.3.1 (build 861) — unreleased candidate

NES now uses green inline insertions, red removed text, compact replacement previews, and responsive stacked/side-by-side line differences. The target has a blue navigation indicator. Clicking it only navigates; proposal surfaces never apply on click. Tab accepts edits on the current or adjacent target line and can continue through visible edits after acceptance. Indentation and ordinary completion take priority over NES. Compatible input rebases displayed candidates; conflicting input dismisses them. Scrolling and resizing reposition previews instead of canceling them. Undo/Redo and explicit dismissal suppress automatic regeneration until fresh editing or an explicit request. Long single-line insertions that do not fit use a compact wrapping preview instead of clipping. Preview typography now shares the editor baseline and line height, with thin borders, minimal padding and a small gutter arrow.

The host minimizes common unchanged prefixes/suffixes before presentation and application, leaving the caret at the final actual change. Preview does not change text or Undo history. Protocol synchronization, history replay and response validation use exact UTF-16 identity, including normalization-only edits. Text-change observers see the new revision before rebasing non-key input. Document identity, language, epoch, revision and UTF-16 snapshot validation, IME and multi-caret refusal remain mandatory. Independent changes inside a wide range are derived as hunks; unchanged islands can be edited without discarding compatible surrounding suggestions. All hunks adopt in one Undo step and the caret ends at the final actual change.

This is a host behavior change, not a claim of identical Copilot model output, provider history, prefetch, latency or experiment settings. The existing official pinned server, authentication, update public key/feed, privacy boundary and signing mechanism remain in use. The joint provider starts inline and NES concurrently, initially prefers usable inline, and gives a previously shown agreeing NES a 10 ms head start. NES/joint requests have no fixed debounce; caret triggers use the public default 10-second recency and 5-second same-line/rejection windows. All already-requested documents retain their synchronized baseline while open; trigger history expires by its public recency window rather than an arbitrary document count. A validated open target in another document receives the first Tab as navigation only and the next Tab as adoption; arbitrary unopened server-selected paths are rejected. Tab/Shift-Tab can move keyboard focus with the session-wide Control-Shift-M mode, and focused native controls keep their keys. NES word/line partial adoption is correctly absent, as in the referenced VS Code inline-edit path. See [the full scope/API audit](NES031_SCOPE_AUDIT.md). No VS Code implementation was copied; public MIT-licensed sources were used as behavioral references. Existing notices are retained.

Release remains gated on native acceptance, independent review and exact-tree distribution verification. Do not merge, tag, publish, change the latest feed, or install over the user's application without the parent review decision.

Expected assets: `CompEditor-v0.3.1-macos-arm64.zip`, matching source and corresponding-source ZIPs, SHA256SUMS and signed appcast.xml. The app and feed must both declare 0.3.1/build 861; fixed download links must use tag v0.3.1.

Final scope follow-up removes the former8-document/32-history limits and fixed2048-grapheme/product diff cutoff. Large sparse edits now retain independent changes and edited islands; actual exploration has the same50ms budget policy as the reference source. Unknown unowned target baselines are still rejected safely; broader unopened-workspace context and full VS Code/model/physical-IME equivalence are not advertised.
