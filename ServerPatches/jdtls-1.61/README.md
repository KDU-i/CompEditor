# Private JDT LS 1.61 diagnostic-version patch

Official JDT LS 1.61 `BaseDiagnosticsHandler` publishes diagnostics without a document version. The client refuses unversioned diagnostics, so the private app requires this minimal server patch for safe Java underlines.

The two complete `upstream/*.java` sources are pinned from Eclipse JDT LS tag `v1.61.0` under their original EPL-2.0 headers. `sources.json` records exact source SHA-256 hashes; `server-input.json` pins the original approved core JAR. `Scripts/patch-jdt-diagnostics.py` compiles with the explicitly supplied existing JDK (`javac --release 21 -proc:none`) and the copied approved server plugins. It performs no download, dependency resolution, installation or project compilation. It fails closed if the pinned source/JAR/patch anchors change.

The patch captures the synchronized version and open-session identity under JDT's existing reconcile lock before diagnostic analysis. The same lock protects text/version updates. Successful edits commit a version only after all buffer edits complete; failed/ignored updates invalidate the version. Null open buffers are refused. Reopening a URI creates a different session identity. The handler publishes only when the captured version/session still match, and attaches that captured version. Unopened, failed-sync, changed and closed/reopened sessions cannot be relabeled as the current document.

Only the app's copied core JAR is changed. External source distributions stay untouched. Upstream JAR signature metadata is removed from the modified private JAR; no signing credentials or operating-system security settings are accessed. All other JAR content and license notices remain. The packaging script bundles complete original and modified EPL source, hash manifests and patch script under `Contents/Resources/ThirdPartyNotices/JDT-Diagnostic-Patch`. The compiler/packaging scripts are Apache-2.0; generated modified Eclipse source remains EPL-2.0. A distributor must preserve the EPL source and notice obligations as well as the separately documented app/runtime licenses and artwork constraints.

Acceptance uses real Java diagnostics, current version changes/clears and a deliberately invalid-range didChange fault. The fault must not publish diagnostics stamped with the failed version. This is a narrowly pinned integration patch, not a claim about arbitrary JDT LS versions or every concurrency interleaving.
